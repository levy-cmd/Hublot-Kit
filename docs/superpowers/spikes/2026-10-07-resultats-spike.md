## Autres constats (décisions du contrôleur)

| Constat | Décision | Section |
|---|---|---|
| Root dans un conteneur peut créer un nœud de périphérique par `mknod`. L'agent est hors du cgroup devices du conteneur : ouvrir ce nœud lit le périphérique de l'hôte. Démontré par un test (`TestReadFileRefusesDevice`). | `Open` / lecture sur fichiers réguliers seulement : `fstat` du descripteur `O_PATH`, refus hors `S_IFREG` (`not_regular`), puis `Reopen` avec `O_NONBLOCK`. Dossiers ouverts pour lister seulement. | §5.1, §6 |
| `/proc`, `/sys` du conteneur contiennent des pseudo-fichiers réguliers lus avec les privilèges hôte de l'agent (ex. `/proc/kallsyms` donne les vraies adresses du noyau). | Refus sur le descripteur résolu, pas sur le chemin (un lien qui y mène est refusé aussi) : après `OpenatInRoot`, `fstatfs` du descripteur `O_PATH` avant tout `Reopen` ; 15 types refusés (procfs, sysfs, cgroup v1/v2, debugfs, tracefs, securityfs, bpffs, configfs, pstore, efivarfs, binfmt_misc, fusectl, selinuxfs, smackfs) → `forbidden_path`, pour `List`, `Stat` et la lecture ; le listing de `/` les montre comme des dossiers ordinaires. `/dev` reste parcourable : ses nœuds sont déjà refusés par la règle des fichiers réguliers. `tarindex` ignore `/proc` et `/sys` (les pseudo-systèmes propres du conteneur ne sont pas montés pour l'archive) et montre `/dev` (en-têtes sans danger, `Open` refuse les périphériques) ; un bind de l'hôte sur `/`, `/proc`, `/sys` ou `/dev` rend l'explorateur indisponible (§5.2 étape 7). | §5.1, §5.2, §6 |
| `CgroupHasID` par sous-chaîne accepterait un faux chemin. | ID de 64 caractères comparé comme composant entier (`docker-<id>.scope` ou `docker/<id>`) ; tout chemin avec un composant `..` refusé. Revue finale : ancrage sur le composant **le plus externe** de forme ID Docker, cgroups enfants acceptés (docker:dind : `docker-<id>.scope/init`), `docker-A.scope/docker-<B>.scope` refusé pour B ; cgroupfs avec `--cgroup-parent` refusé (limite v0.1). | §5.1 |
| Sans `--cgroupns=host`, la forme du chemin cgroup dépend du pilote (cgroupfs : `/../<id>` ; systemd : `/../docker-<id>.scope`). | `--cgroupns=host` imposé partout ; le spike acceptait `/../docker-<id>.scope`, le socle non. Contrôle au démarrage : `/proc/self/cgroup` = `0::/` → détail « lancez l'agent avec --cgroupns=host ». | §5.1, §8 |
| Revue finale : « chemin canonique » d'écriture ambigu (résoudre ou refuser les liens ?). | Écriture et téléchargement de dossier : chemin de la requête nettoyé, sans lien sur toute la chaîne (`openat2` `RESOLVE_IN_ROOT\|RESOLVE_NO_SYMLINKS\|RESOLVE_NO_MAGICLINKS`, ou l'index) ; tout lien → nouveau code `link_in_path` ; ce chemin exact part vers `PutArchive` / `GetArchive`. | §3, §5.3, §5.4, §6 |
